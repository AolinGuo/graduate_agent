# 工商投诉数据分析系统 - 集成仪表板

## 功能特点

### 1. 核心统计指标
- **投诉总量**: 显示筛选时间范围内的投诉总数
- **涉及企业数**: 统计涉及投诉的企业数量
- **涉及行业数**: 统计涉及投诉的行业分类数量
- **月内重复投诉企业数**: 识别在同一月份内有多次投诉的企业

### 2. 投诉趋势分析
- **多时间粒度**: 支持按天、按周、按月查看投诉趋势
- **交互式图表**: 使用D3.js实现的美观投诉趋势图
- **实时筛选**: 通过日期范围筛选，实时更新趋势数据

### 3. 企业投诉排名
- **TOP 10排行榜**: 显示投诉量最多的前10家企业
- **可视化排名**: 前三名企业有特殊的视觉标识
- **详细信息**: 显示企业名称和具体投诉数量

### 4. 时间序列分析
- **ACF自相关分析**: 分析投诉数据的自相关性
- **STL季节性分解**: 将时间序列分解为趋势、季节性和残差分量
- **可选功能**: 通过开关控制是否显示高级分析功能

## 技术架构

### 前端技术栈
- **Vue 3 + Composition API**: 响应式前端框架
- **Element Plus**: UI组件库
- **D3.js**: 数据可视化图表库
- **Pinia**: 状态管理
- **Axios**: HTTP客户端

### 后端技术栈
- **Flask**: Python Web框架
- **Pandas**: 数据处理和分析
- **Statsmodels**: 时间序列统计分析
- **NumPy**: 数值计算

## API接口

### 仪表板统计接口
```http
POST /dashboard/stats
{
  "start_date": "2023-01-01",
  "end_date": "2023-12-31"
}
```

### 趋势数据接口
```http
POST /dashboard/trend
{
  "start_date": "2023-01-01",
  "end_date": "2023-12-31",
  "period": "day"  // 可选: day, week, month
}
```

### 时间序列分析接口
```http
POST /analysis/time-series
{
  "start_date": "2023-01-01",
  "end_date": "2023-12-31",
  "methods": ["acf", "stl"]
}
```

## 数据字段要求

系统要求输入数据包含以下关键字段：

- `市派单时间`: 投诉的派单时间（用于时间分析）
- `企业名称`: 被投诉的企业名称
- `行业分类`: 企业所属行业分类
- `问题分类`: 投诉问题的分类
- `问题详细描述`: 投诉的具体描述

## 部署说明

### 1. 后端部署
```bash
cd server
pip install -r requirements.txt
python run.py
```

### 2. 前端部署
```bash
cd client
pnpm install
pnpm run dev
```

### 3. 访问系统
- 前端地址: http://localhost:3333
- 后端API: http://localhost:8888

## 使用说明

### 1. 时间范围筛选
- 系统会自动加载数据的时间范围作为默认值
- 用户可以通过日期选择器调整分析时间范围
- 修改时间范围后，所有统计数据会自动更新

### 2. 投诉趋势查看
- 点击"按天"、"按周"、"按月"按钮切换时间粒度
- 鼠标悬停在趋势图上可查看具体数值
- 支持缩放和平移操作

### 3. 企业排名分析
- 显示投诉量最多的前10家企业
- 金、银、铜牌样式标识前三名
- 点击企业名称可查看详细信息（待扩展）

### 4. 时间序列分析
- 开启"显示时间序列分析"开关
- 点击"执行分析"按钮进行ACF和STL分析
- 分析结果包括自相关图和季节性分解图

## 注意事项

1. **数据格式**: 确保输入数据的日期字段格式正确
2. **性能优化**: 大数据量时建议适当调整时间范围
3. **浏览器兼容**: 建议使用现代浏览器（Chrome, Firefox, Edge）
4. **依赖安装**: 后端需要安装statsmodels等科学计算库

## 故障排除

### 常见问题

1. **后端启动失败**: 检查Python依赖是否完整安装
2. **前端图表不显示**: 确认D3.js库正确加载
3. **时序分析失败**: 检查数据量是否足够（至少需要14个数据点）
4. **API调用错误**: 确认后端服务正常运行且CORS配置正确

### 调试建议

1. 查看浏览器控制台的错误信息
2. 检查后端日志输出
3. 验证数据格式和API响应
4. 确认网络连接和端口配置
